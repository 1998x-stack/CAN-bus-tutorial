第 29 章 · 低功耗与网络管理

节点睡着了，谁还在听 CAN 总线？

汽车熄火之后，若每一条报文都唤醒所有 ECU，休眠电流就失去意义。本章从电源域出发，分清普通总线唤醒和硬件选择性唤醒，最后用占空比而非“芯片很省电”估算整机电流。

电源域休眠状态机选择性唤醒功耗计算器配置与测试资料

29.1 MCU 睡了，并不代表收发器也睡了

一个 CAN 节点通常有多个电源域：MCU、CAN 控制器、外部收发器、电源管理芯片、传感器和外部电平网络。低功耗目标必须以整板、实际供电路径定义，不能仅引用 MCU 的 Stop 模式典型电流。

先做电流账本：逐项列出工作、待机、休眠、唤醒瞬态的消耗，并明确测量位置（电池输入端/板上稳压输出端）。如果保留外部调试器、USB 转串口、LED，测得的很可能不是产品休眠电流。

29.2 正确的睡眠流程是一台状态机

“空闲 5 秒就睡”只是应用策略，不是所有 CAN 节点的协议要求。休眠前需要禁止新业务、等待关键事务完成或明确放弃，清理中断与队列，配置好唤醒路径，再由 MCU/控制器/收发器分别进入适配的低功耗态。

  1. 请求低功耗：应用同意停发；核实需要完成的 TX，并处理超时而非永远阻塞。
  2. 配置收发器：若要选择性唤醒，先写入并读回 ID、掩码、帧格式、数据比较等器件支持的参数。
  3. 配置 MCU 与 CAN：根据 STM32 家族与板卡设计配置 CAN 控制器睡眠请求、EXTI/唤醒源、外设时钟、电源模式。
  4. 验证恢复：由事件唤醒后，重新使能必要时钟、确认收发器恢复正常通信、重建业务状态；处理总线关闭/故障状态。

29.3 普通唤醒与 Partial Networking 并不是同一回事

支持普通总线唤醒的收发器可以识别定义好的唤醒模式（wake-up pattern），例如符合器件/ISO 要求的显性—隐性—显性序列；这不同于“出现任意一个显性位立即唤醒”。Partial Networking（PN）通过支持该功能的收发器硬件检测有效的唤醒帧 WUF，常见匹配项目包括帧标识符、掩码、DLC/数据字段。CRC 等帧有效性检查也可能影响是否唤醒；具体条件务必查目标器件手册。

模式谁在睡眠时筛选无关报文约束
普通总线唤醒收发器唤醒模式检测逻辑满足有效唤醒模式即可触发不能仅靠 MCU 软件过滤阻止其被叫醒
选择性唤醒 PN收发器的低功耗帧检测逻辑与 WUF 条件不匹配时保持低功耗需专用硬件、正确配置及对噪声/错误帧的验证
MCU 软件过滤MCU 恢复后判断报文可能已造成唤醒电流尖峰无法替代硬件 PN

交互：同一帧会不会叫醒该节点？

教学模型假定帧格式、DLC、CRC 及电气唤醒时序都有效，PN 配置为精确匹配 0x321；真实器件的配置字段更复杂。

PN：0x321 匹配 → 唤醒

NXP TJA1145、TJA1145A 与 TJA1445 不是完全同一个器件，不应直接移植寄存器地址、默认值或诊断标志。这里不提供未经原厂表格核验的 REG_WAKE_ID 虚构代码。

29.4 静态电流要考虑唤醒频率

一个节点即使休眠时只流过几十微安，只要频繁醒来就可能超出整机平均电流预算。将电流在每种状态中的时间加权，才适合评估电池寿命。

Iavg=(1−D)Isleep+DIactive

D 为处于活动态的时间比例；电流单位必须统一。此模型未展开唤醒过渡、发送瞬态、电源转换效率和其他电源域。

平均电流预算器

平均电流 249.5 μA（0.2495 mA）

默认算例：50 μA × 99% + 20,000 μA × 1% = 249.5 μA。频繁误唤醒会改变占空比。

29.5 将寄存器写入变成“可审计的配置契约”

下面是器件无关的接口伪代码，不是可直接编译的 TJA1145 驱动。把每一项映射到选定器件的官方数据手册寄存器表，并对写后读回、错误状态及掉电保留行为测试。

// Pseudocode — vendor-specific SPI/GPIO and MCU power HAL to be supplied.
bool prepare_sleep(void) {
    if (!application_quiesce_with_timeout()) return false;
    if (!tx_completion_or_policy_resolved()) return false;
    if (!transceiver_configure_pn_wuf(0x321, 0x7FF)) return false;
    if (!transceiver_readback_and_verify()) return false;
    if (!arm_transceiver_wake_irq()) return false;
    if (!request_can_controller_sleep()) return false;
    return transceiver_enter_supported_low_power_mode();
}
void on_wake_event(void) {
    restore_clock_and_power_domains();
    transceiver_enter_normal_mode();
    reinitialize_can_and_filters_if_required();
    record_and_clear_wake_reason_per_datasheet();
    application_resynchronize_and_resume();
}

测试矩阵至少包括：正确 WUF、不匹配的有效帧、错误 CRC/噪声、连续报文、休眠期间电源瞬断、本地唤醒、总线故障、唤醒后首帧丢失。让电流探头同步记录唤醒事件与电流曲线；根据具体器件及系统安全需求决定是否允许因总线异常退出 PN 模式。

工程结论：低功耗的验收条件要同时包括 最坏休眠电流、平均电流、误唤醒率、有效唤醒延迟、恢复后首个有效业务响应。仅有收发器睡眠典型值不是系统合格证明。

29.6 技术来源与适用边界

  1. NXP TJA1145 产品资料：具有低功耗与 Partial Networking 能力，设备版本影响规格。
  2. NXP TJA1145A 产品资料：不同版本的功能与 ISO 实现需逐项核查。
  3. NXP TJA1445：Wake-up Frame：WUF 与匹配概念说明，不用于替代 TJA1145 寄存器表。
  4. ST bxCAN HAL API：控制器睡眠请求/唤醒接口，不包括外置收发器的完整电源控制。

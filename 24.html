第24章 CAN 测试工具：为什么抓到报文还不够？

同一条总线，把“协议正确”“电气正确”“容错可靠”分开测。工具不是清单，而是三种不同的观察能力。

24.1 先定位观察层：报文、波形与故障

一台控制器偶发 Bus Off，PCAN-View 记录却只显示一些正常的 CAN 帧。究竟是软件漏处理、位时序不匹配、线束反射，还是硬件在干扰下退出？仅能读取成功接收的报文，并不能证明总线上没有错误位或物理异常。因此需要三条互相补充的证据链。

目标典型工具能看到看不到 / 限制
帧与协议PEAK PCAN、部分厂商 USBCAN、SocketCAN 适配器ID、帧格式、内容、时间戳、接口状态未必能准确反映总线实际模拟波形，错误帧支持依硬件而定
物理层支持 CAN 解码的示波器、CANscope 类设备CAN_H、CAN_L、差分波形、边沿与振铃不能仅从“波形看起来不错”推导出应用 PGN/SPN 正确
容错CANstress 类故障注入设备、受控实验台对预定扰动的错误检测与恢复能力故障种类、幅度、时长受仪器规格与测试安全边界限制

24.2 抓报文：先建立可信的捕获基线

使用 PCAN-View、某款 USBCAN 的配套软件或 Linux can-utils，底层动作通常相同：核对硬件能力 → 选择通道 → 设定位速率和帧格式 → 确认总线连接 → 记录原始帧与时间戳。PCAN 是 PEAK-System 的具体产品系列；USBCAN 则常是不同厂商设备的通用称呼，菜单与驱动不能混为一谈。

  1. 确认被测网络是 Classical CAN 还是 CAN FD，标准帧还是扩展帧，实际标称位速率是多少；J1939 通常需要 29 位扩展帧。
  2. 先用接收或硬件支持的 listen-only 模式捕获，避免测试器意外向实际车辆发送报文。单独用一个分析仪接总线时，还要留意 ACK 与终端配置。
  3. 保留原始 ID、帧格式、DLC、原始数据、单调时间戳和接口错误状态。先抓全量基线，再按 ID 或 PGN 筛选。
  4. 若需要解码 SPN，加载匹配设备与版本的数据库（DBC），并保留原始字节，方便排查缩放、字节序和保留值。

两个过滤器别混淆

“只看标准帧 ID 0x123”和“只看 J1939 PGN 0xF004”不是同一种匹配。更重要的是，不同硬件的 acceptance mask 位极性和寄存器对齐可能不同；不能把某一款设备的 0x7FF 配法当成所有软件的通用设置。PCAN-View 应优先使用当前版本说明的 ID 范围/接收过滤功能。

# Linux SocketCAN 示例：仅适合已正确接入的支持 CAN 的接口
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 500000 listen-only on
sudo ip link set can0 up
candump -L can0,123:7FF          # 标准帧 0x123 的 ID 匹配示意
# J1939 EEC1，匹配 0x18F00400 且忽略低 8 位 SA
candump -L can0,18F00400:1FFFFF00
适用条件：上面的 500 kbit/s 只是示例，必须替换为真实总线速率；listen-only 并非所有 CAN 适配器都支持。标准帧/扩展帧区分需要以工具的帧类型过滤选项或 EFF 标志控制，不能只看十六进制 ID。上述配置是 Linux can-utils 的命令，不是 PCAN-View 菜单步骤。

24.3 看物理层：先测差分，再判断收发器

高速 CAN 的关键不是“CAN_H 一定是 3.5 V”这样一个死数，而是被测收发器数据手册规定的差分电压、共模范围和时序边界。典型高速 CAN 显性态可看到 CAN_H 约 3.5 V、CAN_L 约 1.5 V，差分约 2 V；隐性态两线通常接近 2.5 V，差分趋于 0。具体容限需要查芯片规格，不能把典型值当作所有设备的合格阈值。

断电且隔离主动驱动源后，若线束两端各有一只 120 Ω 终端，跨 CAN_H/CAN_L 测得的等效直流电阻通常接近 60 Ω（120 Ω 并联）。这只是快速排查，不代替反射测试、线束拓扑检查，也不适用于所有带有内部电路的网络。

测量安全：使用接地示波器时要核对探头地与车辆参考地的连接风险，必要时采用合适的差分/隔离测量方案。不要在带电车辆、动力电池或不明接地系统上随意接地、短路或断线。

24.4 受控故障注入：验证检测、隔离和恢复

CANstress 类设备的价值不是“把总线搞坏”，而是在可重复、可量化、受保护的环境下引入扰动，观察错误计数、错误被动状态、Bus Off、重启策略与业务降级。注入能力取决于具体仪器型号；有些侧重扰码/边沿时序，有些侧重线路断路或短路矩阵。

实验台测试记录量避免的错误推论
轻微共模干扰与边沿扰动错误帧、重试、延迟、误码“没丢应用帧”不等于“没有位错误”
终端错配/支线超长的受控复现反射、差分眼图、报文错误不能仅凭总线电阻认定信号完整性合格
安全限流下的短路/开路注入设备保护、故障诊断、恢复路径某一颗高速收发器并不自动拥有单线 CAN 模式

特别是常见高速 CAN 收发器 TJA1040：它不是可自动切换单线 CAN 通信的收发器。单线 CAN 是另一类专用物理层，不要把电气容错测试结果误读成“断一根线还能保证通信”。

24.5 一个能复用的故障定位顺序

看到“偶发 Bus Off”后，避免同时修改三处参数。先记录条件，再把每一步的证据写成能够被他人复验的断言。

  1. 捕获：记录位速率、帧类型、原始日志、TEC/REC 或设备可获得的错误计数，以及触发时间。
  2. 对照：将错误出现时间与供电、负载、温度、波形振铃关联；必要时分别测两根线和差分信号。
  3. 复现：只在隔离的实验台上单因素注入扰动，记录阈值和持续时间，并保留无故障对照组。
  4. 修复与回归：修复线束、供电、终端或时序后，重复同一测试，并以日志/波形/误码计数共同判定改善。
先核对布线、终端、位速率、帧类型和监听模式，再比对示波器差分波形。

可复制的验收记录

测试对象: ECU / 固件版本 / 收发器型号
拓扑: 节点数 / 线长 / 支线 / 终端位置
配置: Classical CAN 或 CAN FD / nominal bitrate / sample point
工具: 分析仪型号+版本 / 探头 / 校准状态
观察: 原始时间戳、ID、DLC、数据、错误状态、波形
故障条件: 幅度 / 持续时间 / 复现次数 / 安全保护
验收: 丢帧、总线恢复、TEC/REC、应用恢复时延

24.6 官方资料与继续学习

软件能力可参考 PEAK-System PCAN-View 文档 与 Linux SocketCAN 文档；单线 CAN 与 TJA1040 的区别可参考 NXP 官方技术社区答复，以及实际收发器数据手册。选型与操作总以实际型号为准。

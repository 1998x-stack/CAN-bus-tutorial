第 28 章 · 网络设计

八个节点同时开口，为什么 CAN 仍然能有序通信？

在一条 500 kbit/s 的总线上，8 个温度节点每 20 ms 各发送 1 帧。我们从连线图出发，依次理解仲裁、负载、时间新鲜度与软件发送队列，最后算出真正需要的带宽。

总线拓扑仲裁与优先级负载计算器同步与新鲜度帧编码验收与资料

28.1 先画出总线，而不是先写发送代码

一条 CAN 总线是共享介质：所有接入节点可以监听帧，只有发送者驱动自己的输出。节点数量并不由 125/250/500 kbit/s 对应某个固定最大值决定，而要联合考虑收发器输入负载、传播延迟、拓扑、线缆以及消息调度。

物理边界：增加节点可能带来电气负载与反射问题，但不等于一定增加帧率。把“节点数限制”换成三张表：电气预算、位时序预算和报文发送周期表。

28.2 仲裁不是报文碰撞后的随机退避

标准 11 位标识符的仲裁按位进行：显性 0 覆盖隐性 1。发送隐性而读到显性的节点退出本轮仲裁；获胜帧继续传输，退出者等待下一次总线空闲再竞争。对于同类数据帧，数值较小的 ID 通常优先。这个过程是 CAN 的无破坏性逐位仲裁，不是“两个数据帧互相撞坏，再随机重试”。

工程上仍需要调度策略：控制闭环与告警使用更高优先级的 ID，周期数据尽量分相位发送，低优先级诊断数据采用限流和队列。不要在硬实时发送路径上无条件调用 HAL_Delay(rand()%5)，这会引入不受控的抖动；先确定截止期与最坏响应时间。

同一 ID 可以在不同时间承载约定的同一种报文，但两个节点同时发送同 ID 而数据位不同可能在仲裁场之后产生位错误。每种生产者/消息类型的 ID 所有权要在网络矩阵中明确；硬件 ACK 也不能证明指定应用消费者已处理消息。

28.3 把“负载很高”换成可复算的数字

以经典 CAN 标准数据帧为例，8 字节帧的 SOF、仲裁、控制、CRC、ACK、EOF 与帧间隔相加，未计填充位时为 111 bit。填充位数量由真实比特模式决定，还要为重传、时钟差异、突发与测量误差留余量。以下计算器默认使用每帧估算 130 bit，这是教学预算而非固定协议帧长。

U=N×LR×T

N = 节点数；L = 估算总线位数/帧；R = bit/s；T = 每节点发送周期（秒）；U 为 0–1 的占用比例。

试算：8 节点温度采集

估算周期帧占用 10.40% · 约 400 帧/s

不含心跳、额外诊断、自动重传；实机应从总线抓包测占用与延迟，再验证优先级和尾部时延。

按默认参数：8 × (1000/20) × 130 = 52,000 bit/s，除以 500,000 bit/s 得 10.4%。即使平均利用率低，也可能在同一时刻出现高优先级突发；负载率不能单独证明截止期一定满足。

28.4 先区分在线、数据新鲜度与时间同步

收到心跳说明“最近见过这个节点”，不能证明它采样数据仍有效。数据帧应携带序号或采样信息，接收端应维护每个 ID 的到达时间，超过约定期限将数据标记为 stale，停止依赖旧值控制执行器。

  1. 监视在线：定期发送私有协议心跳，接收端设置多周期超时；若在 CANopen 网络使用预定义连接集，应遵守其心跳 COB-ID 0x700 + node-id，不能与私有 ID 混用。
  2. 监视新鲜度：上位机按接收时间与连续计数器检出丢失、重放或过期；计数器跳变本身不能定位是哪一层丢失。
  3. 需要同步采样：可在自定义网络发布周期同步事件；如果采用 CANopen，应使用 CiA 301 的 SYNC 机制。软件接收中断时间戳会包含中断延迟，严格同步需要硬件时间戳/测量与误差预算。

28.5 将 4 路温度打包为一个 8 字节帧

定义工程私有协议：节点 1–8 的数据帧 ID 为 0x300 + node；每路温度为有符号 16 位、单位 0.01 °C，按低字节在前传输。这个编码是本课程的约定，不等同于 CANopen PDO 映射。

字节信号类型与精度
0–1温度 1int16, 0.01°C/bit, little-endian
2–3温度 2同上
4–5温度 3同上
6–7温度 4同上
// STM32 HAL / bxCAN 发送示例：hcan 已经配置、启动；节点编号 1..8
#include "stm32f1xx_hal.h"
#include <stdbool.h>
#include <stdint.h>
bool send_four_temperatures(CAN_HandleTypeDef *hcan,
                            uint8_t node, const int16_t temp[4]) {
    if (!hcan || !temp || node < 1U || node > 8U) return false;
    if (HAL_CAN_GetTxMailboxesFreeLevel(hcan) == 0U) return false;
    uint8_t data[8];
    for (uint8_t i = 0U; i < 4U; ++i) {
        uint16_t bits = (uint16_t)temp[i];
        data[2U*i]     = (uint8_t)(bits & 0xFFU);
        data[2U*i + 1U] = (uint8_t)(bits >> 8);
    }
    CAN_TxHeaderTypeDef tx = {0};
    tx.StdId = 0x300U + node;
    tx.IDE = CAN_ID_STD; tx.RTR = CAN_RTR_DATA;
    tx.DLC = 8U; tx.TransmitGlobalTime = DISABLE;
    uint32_t mailbox;
    return HAL_CAN_AddTxMessage(hcan, &tx, data, &mailbox) == HAL_OK;
}

该函数仅证明“已加入控制器邮箱”，不等于物理层发送完成，更不等于远端应用接收。量产要处理 TX 完成/错误回调、队列溢出、超时、总线关闭与恢复策略。

28.6 台架验收：让每个假设可被推翻

  • 断电查两端终端与短支线，示波器测近端/远端边沿与显隐性差分电压。
  • 逐节点上电，核对 ID 唯一生产者、位时序、接收过滤器以及所有节点的 ACK 能力。
  • 抓 60 秒总线日志，对比期望/实测报文率、周期抖动、帧间隔、错误帧与重传。
  • 施加故障：断开一个节点、停发心跳、使发送队列饱和，观察过期值是否被安全处理。

第22章 J1939：29 位 ID 如何变成可理解的发动机数据？

从一帧 0x0CF00401 出发，沿着“标识符 → PGN → SPN → 设备身份”逐层解码。

拆解 ID解码数据设备身份证据与边界

22.1 一串十六进制，为什么能表示发动机转速？

CAN 只规定怎样把一帧可靠地送上总线，却不会告诉你 E0 2E 是电压、温度还是转速。SAE J1939 为重型车辆等网络增加了一层共同语言：PGN 指明这一帧属于哪一组参数，SPN 再指明组内的具体信号。设备还需要通过地址声明告诉网络“谁在发送”。

边界先说清：本章先讨论常见的基于 Classical CAN、29 位扩展标识符的 J1939 报文。传统网络常见 250 kbit/s，但也有 500 kbit/s 等物理层配置；不能仅凭 J1939 三个字母决定波特率。CAN FD、J1939-22 与特定行业配置另行处理。

22.2 先拆 ID：优先级、PGN、地址并不是同一个字段

看一帧 0x0CF00401。它的左边是仲裁优先级，右边是发送者地址；中间的 PF、PS 决定“这是什么数据”。

字段位宽作用例子 0x0CF00401
Priority3 位仲裁优先级，数字越小优先级越高3
R/EDP + DP1 + 1 位数据页相关位（按网络配置解释）0、0
PF8 位PDU Format0xF0（240）
PS8 位PDU Specific0x04（组扩展）
SA8 位Source Address0x01

PF 为 0x00–0xEF 时叫 PDU1，PS 放目标地址（DA），因此 PGN 的最低字节必须清零；PF 为 0xF0–0xFF 时叫 PDU2，PS 是组扩展，属于 PGN。目标地址不是“源地址”，源地址永远从标识符最低 8 位读取。

PGN=(ID≫8)∧MPF

这里的位掩码按 PF 分支取值：PDU1 用 0x03FF00，PDU2 用 0x03FFFF（结果同时保留 R/EDP 和 DP）。

优先级 3 · PGN 61444 (0xF004) · SA 0x01 · 广播参数组

22.3 再拆数据：PGN 是一个容器，SPN 才是信号

PGN 61444 / 0xF004 名为 EEC1（Electronic Engine Controller 1）。其中 SPN 190 是发动机转速，位于数据字节 4 和 5（按 1 起始计数），16 位无符号小端序，分辨率为 0.125 rpm/bit。

SPN字段位置转换
899发动机扭矩模式字节 1，低 4 位枚举编码，非连续物理量
512驾驶员需求扭矩百分比字节 2raw × 1% − 125%
190发动机转速字节 4–5raw × 0.125 rpm

要检查 Not Available、错误指示和保留值，不能直接把所有原始码值都当成有效物理量。定义以适用版本的 SAE J1939-71 / 数字定义或 OEM DBC 为准。

最小可运行解码器

def decode_j1939(can_id, data):
    assert 0 <= can_id < (1 << 29)
    assert len(data) == 8
    pf = (can_id >> 16) & 0xFF
    pgn = (can_id >> 8) & (0x3FF00 if pf < 240 else 0x3FFFF)
    sa = can_id & 0xFF
    rpm = None
    if pgn == 0xF004:
        raw = int.from_bytes(data[3:5], "little")
        if raw not in (0xFFFE, 0xFFFF):
            rpm = raw * 0.125
    return pgn, sa, rpm

frame = bytes.fromhex("00 7D 82 E0 2E FF FF FF")
assert decode_j1939(0x0CF00401, frame) == (61444, 1, 1500.0)
assert decode_j1939(0x18EAFF80, bytes(8))[0] == 59904

22.4 最后找发送者：地址声明不是静态“抢号”

SA 是通信地址，不等同于设备身份。同一个 ECU 的 64 位 NAME 才描述其身份及功能。设备通过 PGN 60928 (0xEE00) 声明 SA；报文 CAN ID 携带声明的 SA，8 字节数据区 携带 NAME（小端字节序）。

NAME 位范围字段位数
0–20Identity Number21
21–31Manufacturer Code11
32–34 / 35–39ECU Instance / Function Instance3 / 5
40–47 / 48Function / Reserved8 / 1
49–55 / 56–59Vehicle System / Vehicle System Instance7 / 4
60–62 / 63Industry Group / Arbitrary Address Capable3 / 1

假设设备 A 和 B 都声明 SA 0x80：各自会比较 NAME 的完整 64 位无符号值，数值较小者保留地址。失去竞争的设备若具备任意地址能力，可按规则尝试其他地址；否则需要报告无法声明。地址声明还有启动、请求、冲突和等待窗口等规则，不能简化成“发完后 250 ms 就永远属于自己”。

工程检查：抓不到业务数据时，先抓 0xEE00 的声明与 SA 是否冲突，再核对 NAME 唯一性及厂商代码配置，而不是随意增加上电延时。

22.5 证据与边界

29 位 ID 与 PDU1/PDU2 路由依据 Linux 内核 J1939 文档；NAME 字段见 Linux UAPI 的 NAME 位定义；EEC1 中 SPN 190 的位置与比例可对照 公开 J1939 PGN 表。公开资料用于复核教学示例，产品中仍应以采购的 SAE 标准及 OEM 通信矩阵为准。

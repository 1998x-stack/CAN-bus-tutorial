第 30 章 · 系统集成与验收

从 STM32 的 ADC 数字到上位机告警，中间究竟发生了什么？

最终项目不应停在“CAN 发送成功”的串口日志上。我们定义一份字节级协议，把传感器→STM32→CAN→USB-CAN→PC 贯通，并用序号、超时和错误计数定位故障，给出可以复算的测试向量。

端到端架构字节契约STM32上位机诊断验收依据

30.1 先明确“完成”的定义

项目选用经典 CAN、11 位标准标识符、500 kbit/s、8 个采集节点和一个只读上位机。每节点每 20 ms 发送一帧 8 字节数据；USB-CAN 适配器只负责接入总线，不自动保证时钟同步、数据格式或应用层可靠交付。

可交付的验收标准应写成可测量条件：例如同一台架连续运行 30 分钟、8 个节点均可解码、无未解释 ID、单节点断线在约定超时内标记 stale、发送队列满时有计数器，且故障恢复不造成不安全的执行器输出。具体延迟门限和丢帧容忍度要由应用风险确定，这里不虚构产品级合格阈值。

30.2 8 字节必须能被两端独立解释

先定应用层映射，再开始编程。这里使用 ID = 0x300 + node（1–8），每帧固定 8 字节，所有多字节量均为 little-endian。负温度用 int16 二进制补码表示；不得直接把带有对齐/填充的 C 结构体原样 memcpy 到总线。

字节字段类型换算/单位
0–1温度int16原始值 × 0.01 °C
2–3压力uint16原始值 × 0.1 kPa
4–5转速uint16原始值 × 1 rpm
6采样计数器uint8每发送一帧加 1，模 256
7状态标志uint8bit 0=传感器故障，其余保留为 0

约定一个有符号向量：温度 −12.34°C、压力 250.0kPa、转速 1450rpm、计数器 7、状态位 1。计算后 8 字节为：

ID: 0x301  DLC: 8
Data: 2E FB C4 09 AA 05 07 01
       |----| |----| |----|  |  |
       -1234   2500   1450  7  1

按协议打包一帧

0x301 · DLC=8 · 2E FB C4 09 AA 05 07 01

教学固定状态字节为 0x01。这个工具仅验证打包/字节序，不模拟 CAN 控制器、误码率或实时性。

30.3 STM32 端：发送邮箱成功不等于链路全程成功

STM32F103 的 bxCAN 标称位时序必须根据真实 APB1 时钟计算。教学条件为 PCLK1 = 36 MHz、BRP = 4、BS1 = 14 TQ、BS2 = 3 TQ、SJW = 1 TQ，因此速率为 36 MHz / [4 × (1+14+3)] = 500 kbit/s，采样点 = (1+14)/18 ≈ 83.33%。GPIO、CAN1 外设时钟、终端电阻、过滤器、NVIC 与收发器的配置仍需在板级初始化中实现。

fbit=fPCLK1BRP×(1+BS1+BS2)=36MHz4×18=500kbit/s sample=1+BS11+BS1+BS2=1518≈83.33% 
// STM32F1 HAL / bxCAN：假设 hcan 已配置、过滤器就绪且 HAL_CAN_Start() 成功
#include "stm32f1xx_hal.h"
#include <stdbool.h>
#include <stdint.h>
extern CAN_HandleTypeDef hcan;
bool send_sample(uint8_t node, int16_t temp_centi,
                 uint16_t pressure_decikpa, uint16_t rpm,
                 uint8_t seq, uint8_t status) {
    if (node < 1U || node > 8U) return false;
    if (HAL_CAN_GetTxMailboxesFreeLevel(&hcan) == 0U) return false;
    uint16_t t = (uint16_t)temp_centi;
    uint8_t data[8] = {
        (uint8_t)t, (uint8_t)(t >> 8),
        (uint8_t)pressure_decikpa, (uint8_t)(pressure_decikpa >> 8),
        (uint8_t)rpm, (uint8_t)(rpm >> 8),
        seq, (uint8_t)(status & 0x01U)
    };
    CAN_TxHeaderTypeDef tx = {0};
    tx.StdId = 0x300U + node; tx.IDE = CAN_ID_STD;
    tx.RTR = CAN_RTR_DATA; tx.DLC = 8U;
    tx.TransmitGlobalTime = DISABLE;
    uint32_t mailbox;
    return HAL_CAN_AddTxMessage(&hcan, &tx, data, &mailbox) == HAL_OK;
}

将 ADC 原始量转换成工程量需要传感器的真实标定曲线、基准电压与上下限处理。此函数接收已经标定并量化的数据；应用必须检测溢出、无效样本和采样同步条件，再决定状态字节。

不建议用“温度传感器 0–5 V”直接接到 STM32F103 的 ADC 引脚：模拟输入允许范围受芯片供电和规格限制，需按实际电路分压、隔离或调理，不能假定 5 V 可直连。

30.4 PC 端：先解析，再判断新鲜度，再显示

对 Linux + 支持 SocketCAN 的 CAN 适配器，可使用 python-can。先在实验台架上配置接口位速率；下面的代码刻意把解码与硬件接收分开。若使用 PEAK/厂商 API，请适配接入层，但不要改变字节协议。

# Linux SocketCAN 示例（需先安装 python-can 并配置 can0 为 500 kbit/s）
# sudo ip link set can0 up type can bitrate 500000
import struct
import time
import can

last_seen = {}
last_seq = {}
def decode_frame(msg):
    if msg.is_extended_id or msg.is_remote_frame or msg.is_error_frame:
        return None
    if not (0x301 <= msg.arbitration_id <= 0x308):
        return None
    if msg.dlc != 8 or len(msg.data) != 8:
        return None
    temp, pressure, rpm, seq, flags = struct.unpack("<hHHBB", msg.data)
    node = msg.arbitration_id - 0x300
    previous = last_seq.get(node)
    gap = previous is not None and seq != (previous + 1) % 256
    last_seq[node] = seq
    last_seen[node] = time.monotonic()
    return node, temp / 100, pressure / 10, rpm, seq, flags, gap

with can.Bus(channel="can0", interface="socketcan") as bus:
    while True:
        msg = bus.recv(timeout=0.05)
        if msg is not None:
            sample = decode_frame(msg)
            if sample:
                print("node/temp/pressure/rpm/seq/flags/gap:", sample)
        now = time.monotonic()
        stale = [node for node in range(1, 9)
                 if now - last_seen.get(node, -1e9) > 0.10]
        # 把 stale 和错误计数传给 UI/日志；不要把旧值冒充实时值。

这里的 100 ms 是教学演示的应用超时策略，不是 CAN 标准规定的时限。500 kbit/s 是通道配置；程序读取到帧还需要用 ID、DLC、版本与字段范围约束，避免错误显示。

30.5 从“没数据”逐层缩小故障范围

观察首查项目不能直接推断
完全收不到帧供电、收发器、线缆、终端、位速率、过滤器不能直接证明 MCU 死机
有报文但字段异常字节序、量程、标定、DLC、版本不能立即归咎物理层噪声
序号跳变/采样过期发送周期、邮箱拥塞、过滤器、PC 处理延迟序号缺口不能定位唯一丢包位置
错误计数上升TEC/REC、LEC、总线波形、ACK 及错误状态不能将总线关闭等同于“节点永久坏了”
PC 看不到 CAN_H/L 电压外接示波器/电压检测通道软件读 ESR 不能代替物理电压测量

在 STM32 bxCAN 的 ESR 中，TEC/REC 分别位于高字节区域，错误状态应结合时序快照记录。建议以上电时刻、同步时刻、采样时刻、传输/接收时刻串起日志；不同来源的时钟不能不校正就直接相减求延迟。

// bxCAN F1 寄存器观测示例（在适当的同步/互斥上下文调用）
uint32_t esr = hcan.Instance->ESR;
uint8_t tec = (uint8_t)((esr >> 16) & 0xFFU);
uint8_t rec = (uint8_t)((esr >> 24) & 0xFFU);
uint8_t lec = (uint8_t)((esr >> 4) & 0x07U);
// 还应读取 BOFF/EPVF/EWGF 等状态位；错误码含义见器件参考手册。

注意上述 LEC 位域的具体定义应以所用 STM32F1 参考手册为准；原始 ESR 快照与 HAL 错误码应同时留存，用于复盘。

  1. 离线黄金向量：不接 CAN，总是得到 2E FB C4 09 AA 05 07 01；解码值分别为 −12.34、250.0、1450、7、1。
  2. 单节点台架：发送固定频率帧，检查发送完成、PC 接收、时间戳及过滤器，不要把添加到邮箱当作接收成功。
  3. 八节点集成：按预期 400 帧/s（不含其他业务）计算理论负载，并与抓包工具测量对照。
  4. 故障注入：停止节点 3，PC 标记 stale；恢复后允许计数器重新同步，并记录异常原因而不静默覆盖历史。
项目闭环：一条报文最终能被验证的，不是“发送函数返回 OK”，而是每层的数据定义、时序约束、异常行为与日志能够独立对上。

CHAPTER 17 · BIT TIMING

500 kbit/s 明明设对了，为什么仍会丢帧？

“速率一致”只是第一道门槛。CAN 节点还要在同一个比特内部选择合适的采样时刻，留出传播延迟、收发器延迟和振荡器误差的裕量。理解位时序，才能解释为什么短线能跑、换成长线就出现错误帧。

阅读路径：位时间 → 延迟预算 → 采样点 → 可复算的 bxCAN 配置

速率与位时间距离与延迟采样点图解配置计算器资料来源

17.1 先把速率翻译成“每位有多长”

经典 CAN 的常见标称速率包括 125、250、500 和 1000 kbit/s，但具体应由网络规格、节点能力、线缆和时序预算共同决定。不是“默认选 500k 就最兼容”：总线上每个节点都必须使用可互通的标称位速率，设备还可能受自身协议或硬件限制。[CiA：CANopen CC 位速率]

tbit=1Rbit
标称速率每比特时间工程读法
125 kbit/s8 μs位时间更长，传播预算相对宽裕
250 kbit/s4 μs中等速率，仍需验证实际网络
500 kbit/s2 μs边沿、节点延迟和采样点更敏感
1 Mbit/s1 μs短位时间，对拓扑与器件提出更高要求

17.2 为什么线一长，同一套参数就不再安全？

CAN 仲裁与应答需要让最远端的总线状态有时间传播回来：节点在位内的采样时刻观察到的必须是已传播、已稳定的真实总线状态。因此，不能仅用“波形是否衰减”或“反射是否回来了”解释速率上限；线缆传播、驱动器/接收器延迟、隔离、支线和振铃都进入预算。[Kvaser：总线延迟]

估算，不是最大线长假定传播速度对应约 5 ns/m，20 m 主干的单程传播约 100 ns，往返约 200 ns。这个值尚未包含收发器、隔离器、支线和同步误差，不能据此直接宣布“20 米可用 1 Mbit/s”。实际设计应使用电缆与器件资料、容差计算和最远端实测。
速率—距离对照表不是标准绝对上限。把“1 Mbit/s 最大 40 m”等经验数字写成通用理论极限会误导选型。相同长度在不同拓扑、节点数量、收发器延迟及温度下可能表现不同。

17.3 一个位在什么位置采样？

名义位时间可拆为 Sync_Seg、Prop_Seg、Phase_Seg1 和 Phase_Seg2。许多控制器（例如 STM32 bxCAN）将中间两段合并成 BS1/TSEG1 暴露给软件。采样点位于 TSEG1 与 TSEG2 的边界，重同步跳宽（SJW）则限定单次重同步的调整幅度。[Kvaser：位时序]

Rbit=fPCLKBRP×(1+BS1+BS2)SP=1+BS11+BS1+BS2

以上 BS1、BS2 和 BRP 都指实际物理计数值，而非某些寄存器字段的零起始编码值。fPCLK 是 CAN 外设实际输入时钟，不能想当然把晶振频率代入。偏晚的采样点一般可给传播留下更多时间，但 BS2 与 SJW 还需满足同步裕量与硬件范围。

17.4 自己算一遍，再查硬件边界

下面是针对 STM32 bxCAN 风格计数的离线计算器。默认例子：PCLK=36 MHz、BRP=4、BS1=14、BS2=3、SJW=1，得到 500 kbit/s 和 83.33% 采样点。这里不自动检查板级电缆延迟和振荡器容差；结果只能说明数学配置自洽。

500.000 kbit/s；18 TQ；采样点 83.33%；每位 2.000 μs。 
# Python 3 · 与上方计算器相同的确定性公式
def bxcan_timing(pclk_hz, brp, bs1, bs2):
    assert min(brp, bs1, bs2) >= 1
    n = 1 + bs1 + bs2
    return pclk_hz / (brp * n), (1 + bs1) / n

bitrate, sample = bxcan_timing(36_000_000, 4, 14, 3)
assert bitrate == 500_000
assert abs(sample - 15/18) < 1e-12
assert abs(1_000_000 / bitrate - 2.0) < 1e-12
上线前最小验证闭环：确认 PCLK 来源与寄存器编码 → 检查 SJW/BS2、拓扑与延迟预算 → 全节点使用可兼容时序 → 在最远端测差分波形、错误计数和长时间总线负载。不同芯片时序参数的允许范围，以芯片参考手册为准。[ADI：CAN 位时序配置]
